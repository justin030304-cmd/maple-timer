# Maple Watch

메이플스토리 개인용 화면 타이머입니다. React 19 + TypeScript 5.9 + Vite 7로 구성하며, 흰 배경과 큰 글자의 한국어 인터페이스를 제공합니다. 실제 화면 공유를 연결하기 전에는 대기 화면을 표시하며, 합성 화면이나 가상 감지 이벤트를 생성하지 않습니다. 화면 공유 영상과 분석은 브라우저 안에서만 처리합니다. 별도 백엔드, API 키, 게임 설치 경로는 필요하지 않습니다.

## 실행

Node.js 20.19 이상(20.x) 또는 22.12 이상을 사용하세요. 현재 개발 환경은 Node.js 24입니다.

```sh
cd /workspace/maple-timer
npm ci
npm run dev
```

Chrome에서 `http://localhost:5173`을 엽니다. 다른 장치나 원격 환경에서 접속할 때는 HTTPS가 필요합니다. `getDisplayMedia()`는 보안 컨텍스트와 사용자의 화면 공유 승인이 필요하며, 공유할 창은 Chrome의 선택창에서 직접 선택합니다.

처음 의존성을 구성하거나 `package.json`을 변경한 경우에는 `npm install`을 사용합니다. 제한된 환경에서 npm 기본 캐시 경로에 쓸 수 없다면 `npm ci --cache /tmp/maple-npm-cache`를 사용하세요.

```sh
npm run build       # TypeScript 검사 + 배포 파일 생성(dist/)
npm run preview     # 빌드 결과 확인
npm test            # 단위 테스트
npm run test:e2e    # Playwright 브라우저 테스트
```

브라우저 테스트는 사용 가능한 시스템 Chromium을 사용합니다. Chromium이 없는 환경에서는 `npx playwright install chromium`으로 Playwright 브라우저를 설치한 뒤 실행하세요. 실제 화면 공유 선택창은 수동 확인도 필요합니다.

## 같은 사이트 주소로 자동 배포

`.github/workflows/deploy-pages.yml`은 `main` 브랜치에 푸시할 때마다 의존성 설치 → 단위 테스트 → 빌드 → GitHub Pages 배포를 실행합니다. 실패한 테스트나 빌드는 배포되지 않습니다. GitHub의 Actions 화면에서 수동 실행도 가능합니다.

현재 저장소는 공개이며, **Settings → Pages → Build and deployment → Source**가 **GitHub Actions**로 설정되어 있습니다. 게시 대상 주소는 [https://justin030304-cmd.github.io/maple-timer/](https://justin030304-cmd.github.io/maple-timer/)입니다. Actions의 **Deploy Maple Watch to GitHub Pages** 실행과 `github-pages` 배포가 성공했는지 확인하세요. 설정 파일이 존재하거나 로컬 빌드가 성공한 것만으로는 사이트가 게시된 상태가 아닙니다.

이 대화에서 계속 수정할 때도 같은 저장소의 `main`에 커밋·푸시하면 기존 게시 주소로 새 버전이 배포됩니다. 파일을 로컬에 저장한 순간에는 배포가 시작되지 않으며, 푸시한 커밋을 기준으로 반영됩니다. 자동 배포가 완료된 뒤 사이트를 새로고침해 새 버전을 확인하세요. Vite의 상대 에셋 경로 설정으로 저장소 이름이 포함된 Pages 경로에서도 실행할 수 있습니다.

동기화되는 것은 사이트 코드입니다. 알림·버프·ROI 설정은 각 브라우저의 `localStorage`에 저장되므로 다른 기기나 다른 사이트 주소로 자동 동기화되지 않습니다. 영상과 캡처 프레임은 게시 이후에도 브라우저 안에서만 처리합니다.

## 사용 방법

1. **화면 공유 시작**을 누르고 Chrome에서 게임 창 또는 화면을 선택합니다. 연결하기 전에는 공유 대기 상태이며, 연결된 실제 영상만 미리보기에 표시됩니다.
2. 룬·버프·경험치·부스터를 각각 켜거나 끕니다. 사용할 모듈의 ROI 편집을 선택한 뒤 영상 위를 드래그해 분석 영역을 지정합니다. 룬은 미니맵만 좁게 지정하세요. 선택 영역은 이동하거나 다시 그릴 수 있고, 좌표를 수치로 조정할 수도 있습니다.
3. 룬 모듈이 켜져 있고 공유 화면과 ROI가 있으면 아이콘 후보 감시가 자동으로 시작됩니다. 버프는 여러 개 등록하고 이름과 지속 시간·미리 알림 시간을 각각 저장할 수 있지만, 버프·부스터는 의미 인식이 아직 구현되지 않아 자동 타이머를 시작하지 않습니다.
4. 경험치 모듈 이름을 눌러 설정을 펼치고 **실험용 픽셀 변화 감시 켜기**를 선택합니다. ROI에 변화가 없을 때 알릴 대기 시간을 지정하세요. 이 기능은 기본값이 꺼짐이며 화면 공유와 ROI가 모두 필요합니다.
5. 알림 설정에서 목소리·음량·말하기 속도를 고르고 **알림 소리 테스트** 또는 룬 카드의 **룬 알림 소리 켜기**를 직접 눌러 소리를 활성화합니다. 설정과 등록한 모듈은 현재 브라우저의 `localStorage`에 저장됩니다.

ROI는 영상 크기에 대한 비율로 저장됩니다. 게임 UI 배치나 해상도가 바뀌면 인식 영역을 다시 확인하세요. 화면 공유를 종료하거나 캡처·분석에 실패하면 상태 표시를 확인할 수 있으며, 해당 상태를 성공적인 감지로 취급하지 않습니다.

## 미니맵 룬 아이콘 감시

찾는 대상은 미니맵 안의 **보라·분홍색과 하늘색이 섞인 작은 마름모 아이콘**입니다. 참고 이미지의 빨간 사각형은 위치를 가리키는 주석이며 감지 대상이 아닙니다. 색상·대칭·마름모 형태를 확인하는 실험적인 규칙 기반 검출로, 이미지 템플릿과의 정확한 일치나 룬 활성화 여부를 판독하는 기능은 아닙니다.

- 룬 모듈은 기본적으로 켜져 있습니다. 화면 공유와 룬 ROI를 지정하면 목표 초당 4프레임으로 해당 영역만 분석하고, 미리보기에 후보 위치를 표시합니다.
- ROI를 화면 전체가 아니라 **미니맵 부분에 좁게** 맞추고 아이콘 주위에 여백을 남기세요. 큰 영역은 축소되어 작은 아이콘을 놓칠 수 있고, 다른 게임 UI가 포함되면 오탐 가능성이 높아집니다.
- 룬 설정의 **아이콘 최소 크기 (px)**·**아이콘 최대 크기 (px)**는 원본 공유 영상 기준이며 기본값은 5~36px입니다. **일치 기준 (점)**은 기본 70점으로, 40~95점 사이에서 조절합니다. 점수는 색·형태 조건의 일치 정도이며 인식 정확도나 확률이 아닙니다. 설정은 브라우저에 저장됩니다.
- 후보가 정상 프레임 3개에서 연속 확인되면 **“룬 아이콘 후보가 감지되었습니다. 미니맵을 확인해 주세요.”**라고 한 번 알립니다. 정상 프레임 8개에서 사라진 뒤에만 재감지를 허용하며, 목표 프레임 속도에서 약 2초에 해당합니다. 알림 사이에는 최소 10초 간격을 둡니다. 프레임 읽기·분석 실패는 아이콘이 사라진 것으로 취급하지 않습니다.
- 아이콘 출현은 룬을 실제로 사용했다는 뜻이 아니므로, 후보 감지만으로 15분 쿨타임 타이머를 시작하지 않습니다. 영상과 색상·UI 배율·겹친 표시에 따라 오탐과 누락이 있을 수 있습니다.

검출 규칙은 합성 이미지와 브라우저 Canvas 스트림으로 검사합니다. 제공된 실제 게임 스크린샷 원본의 픽셀을 기준으로 한 정확도 평가는 수행하지 않았으며, 실전 인식 정확도를 보장하지 않습니다.

## 한국어 음성 알림

기본 알림 방식은 한국어 TTS 음성입니다. 브라우저의 Web Speech API를 사용하며, 설치된 한국어 음성 중 여성 목소리로 알려진 이름을 우선 선택합니다. API가 성별 정보를 제공하지 않으므로 실제 성별이나 여성 음성의 제공 여부를 보장하지 않습니다. **알림 음성** 목록에서 직접 선택하고 테스트로 들어보세요. 빈 선택값은 자동 선택이며, 저장한 음성이 현재 기기에 없으면 사용 가능한 한국어 음성을 다시 선택합니다.

- 알림 방식을 **한국어 TTS 음성** 또는 **기본 알림음**으로 선택할 수 있습니다.
- 음량은 0~100%, 말하기 속도는 0.7~1.3배로 조정하며, 음성 선택과 함께 저장됩니다.
- 한국어 음성이 없거나 음성 재생이 실패하면 사유를 화면에 표시하고 기본 알림음으로 대신 알립니다. 필요한 경우 운영체제에 한국어 음성을 설치하세요.
- 브라우저의 자동 재생 정책 때문에 먼저 **알림 소리 테스트** 또는 **룬 알림 소리 켜기**를 눌러야 합니다. 기기·브라우저에 따라 음성 목록이 늦게 표시될 수 있습니다.
- 음소거하면 화면 알림은 유지하고 소리·음성 안내를 중단합니다. 실제 스피커 출력과 목소리는 사용하는 기기에서 확인해야 합니다.

일부 브라우저·운영체제 음성은 온라인 서비스를 사용해 알림 문구를 처리할 수 있습니다. 기기 음성을 선택하면 로컬 음성 엔진을 사용할 수 있습니다. 어떤 음성을 선택하더라도 게임 영상이나 캡처 프레임을 TTS 서비스에 보내지 않습니다.

## 실제 인식의 범위

| 기능 | 현재 동작 |
| --- | --- |
| 화면 공유·미리보기 | 실제 `getDisplayMedia()` 영상 표시 |
| ROI 선택·편집 | 모듈마다 독립적으로 저장 |
| 룬 아이콘 감시 | 미니맵 ROI에서 보라·분홍/하늘색 마름모 후보를 색·형태 규칙으로 검출하고 알림. 실제 사용 여부와 쿨타임은 판독하지 않음 |
| 버프·부스터 의미 인식 | 실제 검증용 샘플이 없어 미구현. 샘플 필요 상태를 표시하며 자동 타이머를 시작하지 않음 |
| 경험치 감시 | 실험적인 ROI 픽셀 변화 감시. OCR이나 경험치 수치 인식이 아님 |
| 음성 알림 | 사용 가능한 한국어 TTS로 알림 문구 안내. 여성 음성은 이름 기반 우선 선택이며 기기별 제공 여부가 다름 |

경험치 모듈 이름을 눌러 설정을 펼친 뒤 **실험용 픽셀 변화 감시 켜기**를 선택하면 감시를 시작합니다. 화면 공유와 ROI 지정이 필요하며 기본값은 꺼짐입니다.

경험치 감시는 지정한 영역에 변화가 없으면 설정한 시간 이후 알림을 내도록 설계했습니다. 애니메이션·마우스·UI 효과도 픽셀 변화를 만들 수 있고, 작은 숫자 변화는 놓칠 수 있으므로 실제 경험치 획득 여부를 보장하지 않습니다. 분석 영역은 경험치 표시 부분에 좁게 맞추세요.

백그라운드 탭에서는 브라우저가 타이머와 프레임 처리를 지연할 수 있습니다. 탭이 닫히거나 절전 상태가 되면 알림을 보장할 수 없습니다. 이 버전은 게임 내 판단을 대신하는 도구가 아닙니다.

## 개인정보와 구현 경계

- 공유 영상·캡처 프레임은 서버에 업로드하지 않습니다. 분석은 로컬 `<video>`와 Canvas에서 수행합니다.
- 화면 공유는 사용자가 시작하고 종료합니다. 새로고침 후에는 다시 승인해야 합니다.
- 게임 메모리 접근, 자동 키 입력, 게임 조작, 매크로 기능은 구현하지 않습니다.
- 저장되는 항목은 모듈·ROI·알림 설정이며, 공유 영상 자체는 저장하지 않습니다.

이후 실제 게임 샘플을 확보하면 해상도·UI 배율별 검증 데이터를 마련해 룬 후보 검출을 평가·개선하고, 버프·부스터 감지 및 경험치 숫자 인식을 각 모듈에 추가할 수 있습니다. 샘플 기반 검증 전에는 인식 정확도를 주장하지 않습니다.

## 코드 구조와 검증

- `src/components/ScreenPreview.tsx`: 실제 영상 연결, 원본 화면 비율에 맞는 ROI 드래그·이동·방향키 편집
- `src/hooks/useNotificationAudio.ts`: 사용자 동작 기반 소리 활성화, 음성 목록, TTS 실패 시 기본 알림음 처리
- `src/hooks/useRuneDetection.ts`: 공유 영상의 미니맵 ROI 분석, 후보 위치 표시와 연속 프레임 알림 처리
- `src/lib/rune.ts`: 마름모 후보의 색·형태 검출, 중복 알림 억제와 재감지 상태
- `src/lib/speech.ts`: 한국어 음성 선택과 제한된 대기열을 통한 음성 알림 재생
- `src/lib/engine.ts`: 모듈별 독립 타이머 및 감지 상태
- `src/lib/analysis.ts`: 로컬 픽셀 차이 측정. 160×40 ROI 샘플만 메모리에서 처리
- `src/lib/settings.ts`: 검증된 설정 로딩, 손상되거나 차단된 localStorage 처리
- `src/types.ts`: 모듈·ROI·런타임 계약. 버프는 같은 계약의 항목을 추가하는 구조

단위 테스트는 타이머·ROI 좌표·설정 복원·픽셀 차이와 음성 선택·알림 처리를 검증합니다. 룬 검출 테스트는 합성 도형으로 색·형태 구분과 연속 프레임 확인·중복 알림 억제를 검사합니다. 브라우저 테스트는 공유 대기 화면과 설정 조작, ROI 편집, 버프 관리 외에 `getDisplayMedia()` 반환값을 Canvas `captureStream()`으로 대체해 실제 `<video>`→Canvas 분석, 룬 후보 알림, 무변화 알림·변화 후 재시작, 공유 종료·권한 거부·분석 실패를 검사합니다. 합성 이미지나 Canvas 스트림 테스트 통과는 실제 게임 스크린샷의 인식 정확도를 검증한 결과가 아닙니다. TTS 테스트는 브라우저 음성 엔진을 대체하여 한국어 음성 선택과 전달된 문구·음량·속도를 검사하며 실제 목소리나 스피커 출력을 검증한 것으로 취급하지 않습니다. 영상 업로드 본문이 없고 사이트 코드가 외부 서비스를 호출하지 않는지도 확인합니다. 실제 Chrome 화면 선택창과 게임 창 캡처, 설치된 음성과 스피커 출력은 사용자 기기에서 수동으로 확인해야 합니다.
